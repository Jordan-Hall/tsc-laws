# Certificate gallery

Real certificates for the laws of the [certificates demo](../../scripts/ci/certificates-demo), the project the `certificates` workflow checks with the real tools. For a law that certifies, cvc5 wrote an [Alethe](https://verit.loria.fr/documentation/alethe-spec.pdf) proof of its SMT-LIB problem and [Carcara](https://github.com/ufmg-smite/carcara) accepted it. Beside this page are the full problems and proofs, so you can check them yourself. [Proof certificates](../certificates.md) says what a certificate does and does not guarantee.

## What is a certificate?

tslaws proves a law with a solver. A certificate is the solver's proof written to a file, and a separate, independent checker ([Carcara](https://github.com/ufmg-smite/carcara)) re-checks every step of it. You don't have to trust tslaws or the solver: anyone can re-run the check. A law can only get a certificate if the proof format can express it. Today that means whole numbers and true/false logic, so a law about decimal numbers is proved but has no certificate.

### Check a proof yourself

cvc5 wrote each proof from its `.smt2` problem with

```sh
cvc5 --lang smt2 --dump-proofs --proof-format-mode=alethe --proof-granularity=dsl-rewrite --no-proof-alethe-res-pivots --dag-thresh=0 --simplification=none --enum-inst-interleave --cegqi-all --tlimit <proof timeout> problem.smt2
```

and Carcara checks it with the command under each law below. Run it from this directory. Carcara prints `valid` when it accepts the proof.
A `.rare` file holds the rewrite rules the proof cites, which `tslaws` asks the cvc5 binary for.

### How this page is kept current

The `certificates` workflow runs the demo with cvc5 and Carcara, generates this gallery again and fails if the committed one is stale. It compares what the code determines: the laws and their source, whether each is certified, each law's lock hash, and the hash that binds its certificate to the code (the problem, or the Horn clauses for a loop). It does not compare the proofs byte for byte, because proofs and the invariants Z3 finds can differ from run to run without changing what they prove, and the page would drift on every run. Instead the workflow checks that the files here hash as `index.json` says, that this page is what `index.json` renders to, and that Carcara accepts every proof here against its problem with the commands above.

To refresh it after a change, take the `certificate-docs` artifact of the workflow run and copy it over this directory.
