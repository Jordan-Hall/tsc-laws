A TypeScript program consists of source files, resolved dependencies, ambient declarations, libraries, and compiler options. Checking a file requires that environment. An expression's type cannot generally be determined from its source text alone.

## Programs and files

A program has root filenames, module and type-reference resolution, files reached through dependencies, global and per-module declarations, options, and a host providing file lookup. A file has a path, source text, file kind, module format, and declarations.

File kinds distinguish TypeScript, TSX, JavaScript, JSX, and declarations. File extensions and options affect parsing, classification, resolution, and checking. The same text can be accepted as `.ts` but rejected as `.tsx`, or checked differently as a script and a module.

`lib` and `types` contribute declarations. `Promise`, `Array`, `Map`, and `HTMLElement` are declared names, with special compiler handling for some operations. Their members depend on selected libraries. Primitive `string`, the interface `String`, and the constructor value `String` are distinct entities.

## Symbols and meanings

A symbol associates compatible declarations and may have members, exports, and a value declaration. This is a descriptive record, not a mandated implementation structure.

| Declaration             | Value meaning                                 | Type meaning               | Qualifying meaning                          |
| ----------------------- | --------------------------------------------- | -------------------------- | ------------------------------------------- |
| Variable or function    | Binding or callable value                     | None                       | None                                        |
| Class                   | Constructor                                   | Instance type              | Static members are properties of the value. |
| Interface               | None                                          | Structural type            | None                                        |
| Type alias or parameter | None                                          | Named type or parameter    | None                                        |
| Enum                    | Runtime enum                                  | Enum type                  | Members in type and value positions.        |
| Namespace               | Runtime object when applicable                | No instance type by itself | Exported type, value, and namespace names.  |
| Import alias            | According to target and type-only restriction | According to target        | According to target                         |

Only compatible declarations can merge. A namespace can qualify an exported type without itself being a type. See [merging](/typescript/declarations/merging).

```ts
interface Token {
  text: string;
}
const Token = (text: string): Token => ({ text });
const token: Token = Token('name');
```

The annotation requests type meaning; the call requests value meaning. Identical spelling does not make those lookups equivalent.

## Types and signatures

Types include intrinsic special and primitive types, literals, object types, unions, intersections, parameters, and deferred operations. A structured type can have named properties, call signatures, construct signatures, index signatures, and generic arguments.

A property records a name, type, optionality, readonly status, and any declaration-origin restriction. A signature has type parameters, an optional `this` parameter, ordinary parameters, arity, a rest parameter if present, and a return type or predicate. Parameter names generally do not affect compatibility; tuple labels do not create distinct positional types.

A type alias names a resolved or deferred expression rather than introducing a nominal wrapper. Private and protected class members can carry declaration origins that affect compatibility. See [classes](/typescript/types/classes).

## Declared and flow types

A binding's **declared type** comes from its annotation or declaration inference. Its **flow type** at a use can be narrower because of preceding assignments or tests. Subsequent assignments remain bounded by the declared type.

```ts
let value: string | number = 'start';
const length = value.length;
value = 10;
const doubled = value * 2;
// @ts-expect-error: boolean is outside the declared type
value = true;
```

An **apparent type** exposes members for an operation, such as a primitive's library members or a type parameter's constraint. It does not allocate a wrapper at runtime. Widening and normalization are described in [normalization](/typescript/type-system/normalization).

## Contexts and flow

A checking context includes lexical scope, requested declaration meaning, options, a contextual type if available, generic parameters, and flow information. Context can be provisional during overload selection or inference; a context-sensitive expression may be revisited when candidates become available.

A flow state records recognized assignments and tests and their predecessor paths. Joining paths combines possibilities. A terminating path contributes no reachable continuation. The analysis does not execute a called function to discover every mutation or validate an assertion. See [control flow](/typescript/type-system/control-flow).
