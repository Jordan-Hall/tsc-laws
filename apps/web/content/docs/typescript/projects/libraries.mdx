---
title: Standard libraries and ambient environments
description: Library selection, compiler-recognized declarations, environment boundaries, library replacement, and global type packages.
---

Standard libraries declare JavaScript and platform APIs. Their names are not all intrinsic type keywords, and selecting their declarations does not install corresponding runtime implementations.

## Default and explicit selection

`target` supplies a default JavaScript library level; the compiler also includes its default environment libraries where applicable. An explicit `lib` list selects the desired components. `noLib` disables automatic default-library inclusion under its rules. Libraries can reference other components using leading reference directives.

Examples in this specification select ES2022, DOM, and DOM.Iterable. That is an example environment, not a requirement that every TypeScript program have browser globals. Node declarations are normally supplied separately through packages rather than being the intrinsic definition of TypeScript.

## Components

| Family                            | Contracts                                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| ES5                               | Core Object, Function, string/number wrappers, arrays, dates, regular expressions, and utility declarations. |
| ES2015 and later yearly libraries | APIs corresponding to supported JavaScript editions.                                                         |
| Iterable/generator components     | Iterator, iterable, generator, and well-known-symbol relationships.                                          |
| Promise components                | Promise construction, chaining, and fulfillment typing.                                                      |
| Collection components             | Map, Set, weak collections, and corresponding generic members.                                               |
| DOM/DOM.Iterable                  | Browser platform names and iterable integration.                                                             |
| WebWorker components              | Worker environment declarations.                                                                             |
| ScriptHost                        | Legacy scripting-host declarations.                                                                          |
| ESNext components                 | APIs/proposals modeled by this compiler edition, including supported disposable and iterator contracts.      |

Combining incompatible environment libraries can produce duplicate or conflicting globals. `skipLibCheck` can hide internal conflicts but does not establish an accurate runtime environment.

## Compiler-recognized contracts

The checker uses particular declaration relationships for arrays, tuples, Promise-like awaiting, iteration, disposal, JSX, and intrinsic utility types. A user declaration can merge compatible members into a global interface, but replacing the required structure incorrectly can alter checking or produce global diagnostics.

`Array<T>` and `ReadonlyArray<T>` have special container relationships. `PromiseLike<T>` supplies a thenable contract. `Iterator`/`Generator` separate yield, return, and next-input types. `Disposable`/`AsyncDisposable` use corresponding symbol methods. `ThisType` and intrinsic utility names have compiler-recognized roles. These are distinct from arbitrary structurally named application interfaces.

## Library replacement

The compiler supports relevant package-based library replacement, controlled in this edition by `libReplacement`. A project can therefore use a selected replacement declaration package instead of assuming the bundled platform declarations always win. Record replacements when comparing type behavior.

Version changes to libraries can alter inferred overloads or available members even when source and explicit options remain unchanged. A specification observation should identify the library edition as well as the compiler edition.

## Type packages and globals

`types` limits automatically included visible type packages. `typeRoots` changes discovery roots. Imported modules can still bring declarations into the program; restricting automatic global types is not a prohibition on all imported package types. Ambient declarations can advertise APIs absent at runtime, so checking is not a deployment capability test.

## Runtime correspondence

ECMA-262 defines JavaScript built-ins and their execution. Host standards define browser and other platform APIs. This specification describes TypeScript's declaration/checking relationship to those environments rather than duplicating every runtime built-in algorithm. A polyfill, loader, or platform implementation remains a separate runtime dependency.
