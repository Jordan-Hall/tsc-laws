---
title: Project references and incremental builds
description: Split a program into buildable projects and track reusable compiler state.
---

Project references connect separately configured projects. A referenced project generally exposes declaration output as its type boundary. Build mode coordinates those projects in dependency order.

```json
{
  "files": [],
  "references": [{ "path": "./packages/core" }, { "path": "./packages/server" }]
}
```

Each referenced project needs the configuration required by project references, including `composite`. A solution configuration can have an empty `files` list to avoid compiling the same sources again at the solution root.

## Composite projects

`composite` imposes constraints on file inclusion and output structure and enables the declaration boundary needed by dependents. It is not simply an alias for enabling every incremental option.

An ordinary `-p` invocation checks one selected project; it does not automatically build all referenced dependencies first. Use build mode for orchestration.

```sh
tsc-ts --build tsconfig.json
tsc-ts --build --watch tsconfig.json
tsc-ts --build --clean tsconfig.json
```

## Incremental state

`incremental` and build mode can record `.tsbuildinfo` state. That file is compiler build information, not a public API or runtime artifact. Its location can be configured with `tsBuildInfoFile`.

Cache keys must consider source inputs, dependencies, options, and compiler version. Sharing a stale output directory can make a build appear current while unrelated old files remain present.

## Errors and rebuilding

Build behavior after errors is version-sensitive. Modern upstream TypeScript can continue building downstream projects after intermediate errors; `stopBuildOnErrors` controls stopping in supported versions. Do not assume every build mode always behaves like `noEmitOnError`.

## Cleanup

`--clean` removes known build outputs; it is not a general directory-cleaning command. Inspect emitted file lists when changing output layouts.

See [project references](https://www.typescriptlang.org/docs/handbook/project-references.html), [TypeScript 5.6 build changes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-6.html#allow---build-with-intermediate-errors), and [compatibility](/compiler/compatibility).
