---
title: JSX
description: JSX syntax, intrinsic elements, component types, and output modes.
---

JSX is expression syntax embedded in JavaScript-like source. TypeScript parses JSX in `.tsx` files and checks it using the configured JSX type declarations. JSX is not specific to one runtime framework.

## Intrinsic elements

Lowercase element names are ordinarily checked against `JSX.IntrinsicElements`. Component names resolve to values. The framework's declarations supply the namespace and element rules used in real projects.

```tsx
declare global {
  namespace JSX {
    interface Element {}
    interface IntrinsicElements {
      label: { text: string };
    }
  }
}
const element = <label text="Name" />;
// @ts-expect-error: text is required by this intrinsic element
const invalid = <label />;
```

This example supplies a minimal namespace for checking with preserved JSX. It does not provide a JSX runtime.

## Components and attributes

Function and class components are checked according to the library's JSX contract. Props, children, and special attributes depend on those declarations; they are not universally the same for every JSX library.

`JSX.ElementType` lets compatible libraries define which values can be used as element tags independently of the produced element type.

## Output modes

`jsx: "preserve"` retains JSX for another transform. `react` uses the classic factory transform. `react-jsx` and `react-jsxdev` use automatic runtime imports. `jsxImportSource` selects the automatic runtime package.

Selecting a mode does not install the package or make it available to the runtime loader.

## Assertions and generics

Angle-bracket type assertions conflict with JSX parsing; use `as` assertions in `.tsx`. Some generic arrow functions also need disambiguation, such as a trailing comma in `<T,>`.

See [JSX](https://www.typescriptlang.org/docs/handbook/jsx.html), [JSX.ElementType](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-1.html#decoupled-type-checking-between-jsx-elements-and-jsx-tag-types), and [emit](/typescript/projects/emit).

## JSX syntactic categories

```text
JsxElement = '<' TagName Attributes '>' Children '</' TagName '>' ;
JsxSelfClosing = '<' TagName Attributes '/>' ;
JsxFragment = '<' '>' Children '</' '>' ;
Attribute = AttributeName [ '=' ( StringLiteral | '{' Expression '}' ) ]
          | '{' '...' Expression '}' ;
Child = JSX text | JsxElement | JsxSelfClosing | JsxFragment
      | '{' [ Expression ] '}' ;
```

Tag names and attribute names use the JSX-specific name grammar, including supported qualified or namespaced forms. Opening and closing tags must match. Text and quoted attributes are scanned in JSX mode, with their own entity and whitespace behavior. A TSX file's JSX parse goal makes angle assertions unavailable.

## ResolveJsxTag

For a tag:

1. Classify it as intrinsic or value based on JSX naming syntax.
2. For an intrinsic tag, resolve the relevant member or index contract of `JSX.IntrinsicElements`.
3. For a value tag, resolve its value and eligible call/construct/component contract.
4. Apply `JSX.ElementType` when declared to determine eligible tag values independently of element result shape.
5. Determine attribute and child requirements through the library's namespace contract.

The namespace can come from the classic factory or automatic runtime declarations, with the supported fallback rules. A global `JSX` namespace is not always the selected namespace in every automatic-runtime setup.

## Attribute contracts

Function component parameters and class component contracts supply props. `JSX.ElementAttributesProperty` can identify the class member used for attributes; `JSX.ElementChildrenAttribute` names the property to which children contribute. `JSX.IntrinsicAttributes` and `JSX.IntrinsicClassAttributes` provide special framework-controlled attributes.

`JSX.LibraryManagedAttributes` can adjust checking based on the component and its props, including library-specific default behavior. This is library machinery, not a universal rule that every JSX framework implements React's exact props semantics.

Required props, value types, and spread attributes are checked. Nonidentifier attribute spellings such as hyphenated names have special unknown-attribute behavior; not every unlisted attribute is handled identically to a normal identifier. Spread ordering follows runtime source order, and checking cannot always establish an exact final key set.

## Children and output

Children contribute to the selected child property contract and can have framework-dependent accepted types. JSX expressions have the library's `JSX.Element` relationship; that does not necessarily preserve all information about the original component or its props.

`preserve` retains JSX, `react` uses the classic factory, and automatic modes use runtime imports. `react-native` has its own preservation/output conventions. `jsxFactory`, `jsxFragmentFactory`, `jsxImportSource`, and JSX pragmas select corresponding contracts. Type checking does not install a framework or a runtime implementation.

## Generic components and parsing

Supported JSX syntax can provide explicit component type arguments. A generic arrow in TSX requires lookahead-disambiguating syntax where needed, often `<T,>`. These parse restrictions do not alter generic inference elsewhere. A namespace tag or member expression tag must still resolve through the appropriate value contract.
