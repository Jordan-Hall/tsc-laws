Narrowing reduces the possible types of a value at a use site. The declared type still determines which future assignments are allowed.

```ts
function format(value: string | number) {
  if (typeof value === 'string') return value.toUpperCase();
  return value.toFixed(2);
}
```

## Guards

`typeof`, equality comparisons, `instanceof`, and the `in` operator can narrow values. Truthiness checks also narrow, but reject useful falsy values such as `0` and `""`. Check nullish values explicitly when those values should remain valid.

`typeof null` is `"object"`; an object guard alone does not exclude `null`. Optional properties can participate on both sides of an `in` check, since they may be present or absent.

## Declared and flow types

```ts
let value: string | number = 'text';
value.toUpperCase(); // current flow type is string
value = 3;
value.toFixed(); // current flow type is number
```

The assignment to `3` is legal because the declared type includes `number`.

## Predicates and assertions

A predicate declares a relationship between a boolean result and a parameter's type. The checker trusts that contract; it does not prove that the implementation identifies exactly those values.

```ts
function isString(value: unknown): value is string {
  return typeof value === 'string';
}
function assertString(value: unknown): asserts value is string {
  if (!isString(value)) throw new Error('Expected string');
}
```

Inferred predicates are supported for some function bodies, with constraints on returns and parameter mutation. An explicit predicate with incorrect runtime logic can make an accepted program fail.

## Boundaries

Mutation and aliasing complicate flow analysis. The checker does not model every effect of a called function or every later callback execution. Keep a narrowed value in a stable local binding when subsequent mutation would invalidate the assumption.

See [narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html) and [statements](/typescript/language/statements).

## Guard operations

The checker recognizes `typeof`, equality and inequality, truthiness, `in`, `instanceof`, discriminant tests, assignments, and declared or inferred predicate calls. Each guard computes facts for true and false branches. The result depends on the checked reference, union constituents, options, and whether a fact remains valid at the use.

| Guard                   | Recognized consequence                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------- |
| `typeof x === 'string'` | Retain the string possibilities on true and exclude them on false.                     |
| `x === null`            | Refine the null possibility under strict null checking.                                |
| `x != null`             | Exclude both null and undefined on true.                                               |
| `if (x)`                | Exclude recognized falsy alternatives; may retain ambiguity for broad primitive types. |
| `'key' in x`            | Refine alternatives by required/optional property presence.                            |
| `x instanceof C`        | Refine through the constructor/prototype and predicate rules.                          |
| `x.kind === literal`    | Select compatible discriminated object alternatives.                                   |

`typeof null` is the string `"object"`, so an object test alone does not exclude null. Truthiness also excludes values such as empty strings and zero; a guard intended to exclude only missing values should use a nullish comparison instead.

```ts
function present(value: string | null) {
  if (value !== null) return value.toUpperCase();
  return 'missing';
}
```

## Equality and overlapping types

Equality between two references can narrow them toward shared possibilities. An equality test does not validate an arbitrary assertion attached to an operand. Comparability checks can also diagnose operands with no recognized overlap.

Switch cases apply equality-like discriminant facts. The default path excludes recognized cases, but the language does not universally require an exhaustive switch. Assigning the remaining value to `never` creates an explicit exhaustiveness check.

## Property presence

For `in` tests, required properties select the true branch, missing properties select the false branch, and optional properties can participate in both. A previously unlisted property can narrow an object toward a record-like type containing that key with an unknown value, allowing subsequent value-type tests.

```ts
function label(value: unknown) {
  if (value && typeof value === 'object' && 'name' in value && typeof value.name === 'string') {
    return value.name.toUpperCase();
  }
  return undefined;
}
```

Presence and definedness differ: a present property can contain undefined. With `exactOptionalPropertyTypes`, a presence test can distinguish an absent optional property from an allowed present value more precisely.

## Correlations and invalidation

Recognized discriminants and const destructuring can retain relationships between members of a union. Arbitrary aliases, separately mutable variables, dynamic keys, and unrelated generic parameters do not receive every such correlation. Writing a tracked property or its containing reference can invalidate relevant facts.

Some call effects are intentionally not modeled, so accepted narrowing can outlive a runtime mutation through another alias. The [control-flow clause](/typescript/type-system/control-flow) defines that boundary. A guard must not be presented as immutable validation of all future observations of an object.

## Generics and special types

Narrowing a generic value can intersect its current type with a recognized requirement, but it need not rewrite every use of the generic parameter. `unknown` becomes usable after suitable tests; `any` bypasses much of ordinary checking and does not provide the same safety boundary.
