---
title: Type assertions and satisfies
description: Assert a type, preserve literals, and check a shape without runtime conversion.
---

A type assertion tells the checker to view an expression as another type. It does not convert or validate the value. Direct assertions generally require sufficient overlap between source and target types.

```ts
declare const input: unknown;
const name = input as string;
// A runtime check is still needed before treating external input as a string.
```

## Double assertions

An assertion through `unknown` can bypass the overlap restriction. This weakens checking and does not make the value correct.

```ts
const value = 'text' as unknown as number;
// The runtime value is still "text".
```

## Non-null assertions

`value!` removes `null` and `undefined` from the expression's type. It does not check for them at runtime. A definite assignment assertion on a declaration likewise suppresses an initialization check without assigning a value.

Prefer a guard when missing values are possible during execution.

## Const assertions

`as const` retains primitive literal types, makes object-literal properties readonly, and makes array-literal positions a readonly tuple. It applies to suitable literal expressions, not arbitrary expressions needing conversion.

```ts
const request = { method: 'GET', path: '/users' } as const;
const method: 'GET' = request.method;
```

## `satisfies`

`expression satisfies T` checks assignability to `T` while preserving the resulting expression type rather than replacing it with the annotation. The target can still supply contextual typing.

```ts
const colors = {
  red: [255, 0, 0],
  blue: '#0000ff',
} satisfies Record<string, string | [number, number, number]>;
colors.blue.toUpperCase();
```

It does not provide runtime validation and can still perform excess property checks on a fresh object literal.

See [type assertions](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#type-assertions) and [`satisfies`](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-9.html#the-satisfies-operator).
