title: This types and receiver checking
description: Polymorphic this, explicit receiver parameters, contextual this, lexical arrows, and static receivers.
---

The runtime meaning of `this` follows ECMAScript call and lexical binding rules. TypeScript adds a type for that receiver and checking contracts that can distinguish a method's intended invocation from an unbound call.

## Explicit `this` parameters

A signature can start with a pseudo-parameter named `this`. It provides a receiver type, is not counted as an ordinary argument, and is erased from output. A call requiring a receiver must supply a compatible receiver through its call form or the applicable `call`/`apply` relationship.

```ts
function increment(this: { count: number }, amount: number) {
  this.count += amount;
}
const state = { count: 0, increment };
state.increment(1);
// @ts-expect-error: the standalone call has no compatible receiver
increment(1);
```

`this: void` can state that a callback must not depend on a supplied object receiver. An arrow captures its lexical `this`; it does not gain a dynamic receiver because it is stored as an object property.

## Polymorphic `this`

In an instance member type, `this` can denote the current subtype rather than just the declaring class. A method returning `this` preserves fluent relationships through subclasses.

```ts
class Builder {
  ready(): this {
    return this;
  }
}
class NamedBuilder extends Builder {
  name = 'item';
}
const result: NamedBuilder = new NamedBuilder().ready();
```

This is a type relationship, not automatic runtime cloning. A method returning another unrelated object does not satisfy `this` merely because it has the declaring class's public members; future subclasses can add more requirements.

## Contextual receivers

Object literal methods can receive context from their surrounding object type. `ThisType<T>` is a library marker recognized in contextual object-literal checking and must be used with the applicable `noImplicitThis` context. It provides no members itself and does not rewrite runtime invocation.

```ts
type Descriptor<D, M> = { data: D; methods: M & ThisType<D & M> };
const descriptor: Descriptor<{ count: number }, { increment(): void }> = {
  data: { count: 0 },
  methods: {
    increment() {
      this.count += 1;
    },
  },
};
```

The descriptor does not itself install the methods onto the data object. A library consuming such a descriptor must establish the promised runtime receiver.

## Implicit and static contexts

`noImplicitThis` diagnoses uses where the receiver would have an inappropriate implicit any type. It is distinct from `noImplicitAny` on ordinary parameters. Top-level `this`, nested functions, arrows, class instance members, and static members have different receiver contexts.

A static member's receiver relates to the constructor side, not the instance side's generic arguments. A nested ordinary function does not automatically inherit the enclosing method's receiver type. `super` accesses use heritage and runtime receiver rules; they are not ordinary properties on an arbitrary structural `this` type.
