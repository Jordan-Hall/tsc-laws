---
title: Mapped types
description: Transform properties, modifiers, and keys using a type-level mapping.
---

A mapped type creates properties by iterating over a union of keys. A mapping over `keyof T` can transform a shape while preserving relationships between each key and its value.

```ts
type Flags<T> = { [K in keyof T]: boolean };
type UserFlags = Flags<{ name: string; age: number }>;
const flags: UserFlags = { name: true, age: false };
```

## Modifiers

`readonly` and `?` can be added or removed. Prefix `-` removes a modifier; an omitted `+` adds it.

```ts
type MutableRequired<T> = { -readonly [K in keyof T]-?: T[K] };
type Input = { readonly name?: string };
type Output = MutableRequired<Input>; // { name: string }
```

Mappings that directly preserve the relationship to `keyof T` can preserve existing modifiers unless changed. Removing optionality interacts with `undefined` and `exactOptionalPropertyTypes`; absence and a property's explicitly declared value type are separate concerns.

## Key remapping

Use `as` to produce a different key type. Mapping a key to `never` omits it.

```ts
type WithoutId<T> = {
  [K in keyof T as Exclude<K, 'id'>]: T[K];
};
type User = WithoutId<{ id: string; name: string }>;
```

Template literal types can construct new string names. Filter to string keys when the operation requires strings; `keyof T` can also include numbers and symbols.

## Arrays and tuples

Certain homomorphic mappings preserve array or tuple structure. For example, applying `Readonly` to an array produces a readonly array. A key remapping can change that behavior and produce an ordinary object shape instead.

Mapped types do not loop over runtime values or create objects. They describe the type of an object an implementation must still construct.

See [mapped types](https://www.typescriptlang.org/docs/handbook/2/mapped-types.html) and [template literal types](/typescript/type-operators/template-literal-types).

## Mapping operation

For `{ [P in K]: V }`, resolve the key type `K`, establish the mapped parameter `P`, and instantiate the value expression `V` for each permitted key or index domain. Mapping is a type computation; it does not enumerate or copy a runtime object.

The source key domain must satisfy the permitted property-key relationship. `as` remaps each key; producing `never` filters it out. Multiple original keys remapped to the same resulting key can combine their value possibilities. Remapping is not a promise to rename runtime properties.

```ts
type Prefix<T> = { [K in keyof T as K extends string ? `get${Capitalize<K>}` : never]: () => T[K] };
type Getters = Prefix<{ name: string; count: number }>;
const getters: Getters = { getName: () => 'Ada', getCount: () => 1 };
```

## Homomorphic mappings

A supported mapping directly over the keys of a type parameter can preserve source member structure, including optionality and readonly status. Without remapping that changes the structure, homomorphic mappings can transform arrays and tuples element-wise while preserving positional structure. A mapping over an arbitrary independent key set does not necessarily get the same preservation.

```ts
type Nullable<T> = { [K in keyof T]: T[K] | null };
const tuple: Nullable<[string, number]> = [null, 1];
const array: Nullable<string[]> = ['a', null];
```

A remapping clause can change array/tuple behavior because it constructs remapped keys rather than simply preserving source positions. Applying a homomorphic mapped type to a primitive can retain that primitive's special mapped behavior rather than manufacturing an arbitrary wrapper record.

## Modifier operations

`readonly` and `+readonly` add readonly; `-readonly` removes it. `?` and `+?` add optionality; `-?` removes it. Omitted modifiers preserve source modifiers in the appropriate homomorphic context. Under strict null checking, removing an optional modifier can also remove the undefined component associated with optionality; it must not be summarized as always removing every explicitly written undefined from every property type.

```ts
type RequiredMutable<T> = { -readonly [K in keyof T]-?: T[K] };
const value: RequiredMutable<{ readonly count?: number }> = { count: 1 };
value.count = 2;
```

## Deferred and finite mappings

When the key set depends on an unresolved parameter, the mapped type remains deferred. A finite literal union makes finite named members; a broad key category produces applicable index behavior. A mapped body cannot include independent ordinary property or method declarations alongside the mapping. Combine a separate object through an intersection if both contracts are required.

## Distribution and limits

Homomorphic mappings can preserve and distribute source union structure in supported cases. This behavior differs from assuming that `keyof` itself gathers every key from a union. Remapping, conditional key expressions, and recursion can create large results subject to representation and instantiation limits.
