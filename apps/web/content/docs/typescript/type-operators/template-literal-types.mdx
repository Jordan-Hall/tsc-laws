---
title: Template literal types
description: Construct and match string types using literal patterns.
---

A template literal type combines string literals and interpolated type alternatives. Unions in interpolations produce combinations of possible strings.

```ts
type Action = 'read' | 'write';
type Entity = 'user' | 'file';
type Event = `${Entity}:${Action}`;
const event: Event = 'user:read';
// @ts-expect-error: not one of the generated combinations
const invalid: Event = 'group:delete';
```

## Patterns

An interpolation can contain broader types such as `string` or `number`, making a pattern rather than a finite list.

```ts
type DataKey = `data-${string}`;
const key: DataKey = 'data-user';
type Pixel = `${number}px`;
const width: Pixel = '12px';
```

These types check string compatibility. They do not parse or validate arbitrary strings at runtime, and a numeric template pattern is not a complete specification of a domain-specific numeric format.

## Matching with `infer`

A conditional type can split a string literal by matching a template pattern.

```ts
type Suffix<T extends string> = T extends `data-${infer Rest}` ? Rest : never;
type Name = Suffix<'data-user'>; // "user"
```

The match uses the compiler's type-level string rules. It does not call JavaScript string methods.

## Intrinsic string mappings

`Uppercase`, `Lowercase`, `Capitalize`, and `Uncapitalize` transform string types. Their behavior follows the compiler's string mapping implementation and is not locale-aware formatting.

Large unions can produce a cross product too large for the compiler to represent. Prefer a broader checked pattern or generated declarations when enumerating every combination becomes impractical.

See [template literal types](https://www.typescriptlang.org/docs/handbook/2/template-literal-types.html), [mapped types](/typescript/type-operators/mapped-types), and [conditional types](/typescript/type-operators/conditional-types).

## Template type construction

A template literal type contains fixed text and substituted types. Supported substitutions include string, number, bigint, boolean, null, undefined, and applicable literal/union forms. Symbol types cannot be interpolated into this type syntax. This operation constructs string types; it does not execute a JavaScript template or call a user's `toString` method.

Finite unions in substitutions form combinations across positions. Literal substitutions produce corresponding text alternatives. A broad string placeholder can preserve a pattern such as `prefix-${string}` rather than always collapsing the entire expression to `string`.

```ts
type Route = `/${'users' | 'teams'}/${number}`;
const route: Route = '/users/42';
// @ts-expect-error: fixed text must match the pattern
const invalid: Route = '/projects/42';
// @ts-expect-error: symbol cannot be interpolated into a template type
type SymbolText = `${symbol}`;
```

An interpolated `never` produces no possible strings. A broad numeric placeholder represents strings satisfying the checker's numeric-template matching rules; it is not a promise about every application-specific decimal formatting convention.

## Pattern matching and inference

Conditional types can match fixed segments and infer substituted portions. Inference follows the pattern and its constraints; it is not a general regular-expression engine. Multiple placeholders and empty fixed segments can lead to constrained or ambiguous inference rather than every possible partition of the input string.

Since TypeScript 4.8, constrained primitive inference can parse eligible text and check a round-trip representation. A canonical numeric string can infer its numeric literal; text that does not round-trip can infer a broader numeric type rather than that literal.

```ts
type Parse<T extends string> = T extends `${infer N extends number}` ? N : never;
const canonical: Parse<'100'> = 100;
const noncanonical: Parse<'1.0'> = 2;
```

The second example documents the broader result; it is not runtime number parsing. The original string remains a string value if used at runtime.

## Intrinsic case operations

`Uppercase`, `Lowercase`, `Capitalize`, and `Uncapitalize` are compiler-recognized library intrinsics. They transform known strings and propagate supported pattern structure. They follow JavaScript string casing behavior, not locale-sensitive application rules. A casing operation can change the number of code units in a string.

```ts
type Event = `on${Capitalize<'click' | 'focus'>}`;
const event: Event = 'onClick';
// @ts-expect-error: the intrinsic operation changes the first character
const lower: Event = 'onclick';
```

## Keys and representation limits

Mapped types can remap string keys with template types; numeric and symbol keys need explicit handling. Pattern index signatures can admit infinite key domains such as `data-${string}`. Neither operation adds or renames runtime properties.

Multiple large finite unions can multiply the number of alternatives and exceed representable-union limits. Broad patterns can be retained without expanding every possible string. The compiler does not promise to construct arbitrarily large finite cross-products.
