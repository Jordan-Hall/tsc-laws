---
title: Indexed access types
description: Select property and element types with T[K].
---

`T[K]` selects the property types of `T` identified by the key type `K`. The key type must be valid for the indexed type.

```ts
type User = { name: string; age: number; active: boolean };
type Name = User['name']; // string
type TextOrNumber = User['name' | 'age']; // string | number
type Value = User[keyof User]; // string | number | boolean
```

An invalid key is rejected; indexed access is not an unchecked lookup of arbitrary properties.

```ts
type User = { name: string };
// @ts-expect-error: no age property exists
type Age = User['age'];
```

## Array and tuple elements

Indexing an array type with `number` retrieves its element type. For a tuple, a known numeric literal retrieves the position's type, and `number` retrieves a union of element types.

```ts
type Entries = { id: string }[];
type Entry = Entries[number]; // { id: string }
type Pair = [string, number];
type First = Pair[0]; // string
type Element = Pair[number]; // string | number
```

## Type keys versus value keys

The brackets of an indexed access type contain a type. A value binding cannot be used directly as that type; use `typeof key` when its value's type is the desired index.

```ts
const key = 'name';
type User = { name: string };
type Name = User[typeof key];
```

## Optional properties

Selecting an optional property includes `undefined` under `strictNullChecks`. Type-level indexed access and runtime indexed reads are related but not identical: `noUncheckedIndexedAccess` adds missing-value checks to relevant value reads.

See [indexed access types](https://www.typescriptlang.org/docs/handbook/2/indexed-access-types.html), [`keyof`](/typescript/type-operators/keyof), and [object types](/typescript/types/objects).

## ResolveIndexedAccess

Given object type `T` and index type `K`:

1. Resolve a known key against named properties and applicable index signatures.
2. For a union index, combine read possibilities from the permitted keys.
3. For a union object, require the operation to be valid across the relevant alternatives.
4. For a generic object or index whose result is unresolved, retain `T[K]` and use constraints to establish available operations.
5. Diagnose invalid keys rather than inventing an arbitrary member type.

```ts
type Model = { name: string; age: number; active?: boolean };
type Name = Model['name'];
type Fields = Model['name' | 'age'];
type Optional = Model['active'];
// @ts-expect-error: this key is not available
type Missing = Model['missing'];
```

Optional member reads include undefined. Type-level indexed access is not automatically the same as every expression-level read under `noUncheckedIndexedAccess`; the expression flag adds missing-index possibilities to uncertain runtime accesses, while a declared signature's value type remains its declared type operation.

## Arrays and tuples

`ArrayType[number]` obtains an array's element type or a tuple's combined position types. A known tuple literal index obtains that position's type. Out-of-range known tuple indices are rejected. A tuple's optional position contributes undefined, and a rest region follows its declared element requirements.

```ts
type Tuple = [string, number?];
type First = Tuple[0];
type All = Tuple[number];
const item: All = undefined;
// @ts-expect-error: the third known position is absent
type OutOfRange = Tuple[2];
```

## Generic key/value relationships

A generic parameter `K extends keyof T` retains the relationship between a selected key and its value type. A broad union key read combines possibilities, but a write through that same uncertain key must satisfy every possible target. The read union is therefore not necessarily an assignable write type.

```ts
function set<T, K extends keyof T>(object: T, key: K, value: T[K]) {
  object[key] = value;
}
set({ count: 0, label: 'item' }, 'count', 1);
```

The function's contract is still subject to inference and aliasing boundaries; it does not freeze an object or validate an unknown key at runtime.

## Keys are types

The contents of the brackets are a type, not a runtime expression. A variable value used as a type name produces a meaning-space error; query its type with `typeof` when appropriate. A query obtaining the broad type `string` does not thereby establish that every string names a valid property.
