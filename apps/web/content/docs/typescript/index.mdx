This specification describes **TypeScript 5.9.3**: accepted syntax, the types assigned to programs, type relationships, declaration checking, and the effect of compiler options on checking and output. It is maintained independently of Microsoft.

## Scope

TypeScript extends ECMAScript. JavaScript evaluation, execution contexts, objects, and built-in runtime operations are defined by [ECMA-262](https://tc39.es/ecma262/). The clauses here describe TypeScript's additional syntax and static semantics. An erased annotation does not introduce a runtime check.

## Version and options

The edition is tied to the [TypeScript 5.9.3 source revision](https://github.com/microsoft/TypeScript/tree/c63de15a992d37f0d6cec03ac7631872838602cb). Its compiler, libraries, and conformance tests resolve behavior that this text leaves unspecified or describes incorrectly. Source citations identify this edition rather than a moving branch.

The **tsc-ts** compiler targets TypeScript-Go **7.0.2**, pinned in [upstream.json](https://github.com/vercel-labs/tsc-ts/blob/main/upstream.json). That separate target does not change this specification's edition. A successful TypeScript 5.9 example check is not a TypeScript 7 or tsc-ts conformance result.

Unless a page states otherwise, examples assume:

- `strict: true`, including `strictNullChecks` and `strictFunctionTypes`.
- `target: "ES2022"` and `module: "ESNext"`.
- `moduleResolution: "bundler"`.
- `exactOptionalPropertyTypes: false` and `noUncheckedIndexedAccess: false`.
- `lib: ["ES2022", "DOM", "DOM.Iterable"]` and `types: []`.

Environment-specific pages explain the options they depend on. A type inferred from an example can change when its context or options change.

## Reading examples

Each TypeScript block is checked independently. Comments reporting inferred types are descriptive; a type-level constraint or assignment can make a particular relationship executable:

```ts
const length: number = 'TypeScript'.length;

// @ts-expect-error: a string is not assignable to number
const invalid: number = 'ten';
```

`@ts-expect-error` requires a diagnostic on the next line; it does not assert its code or wording. Multi-file examples explicitly declare filenames. `// @option:` directives change the default context. JavaScript and shell blocks are explanatory and are not executed by the snippet checker.

## Checking and execution

A type error and a runtime error are different outcomes. A compiler can emit JavaScript from a program with type errors unless `noEmitOnError` is enabled. An accepted program can still fail at runtime, for example after a type assertion describes a value incorrectly.

Read [type erasure](/typescript/language/type-erasure), [assignability](/typescript/type-system/assignability), and [sources and verification](/typescript/sources) for the rules behind those distinctions.
