---
title: Interfaces and type aliases
description: Naming object shapes, extending interfaces, and choosing a declaration form.
---

An interface names an object shape. A type alias gives a name to any type expression, including an object, primitive, union, or tuple. Neither creates a runtime value.

```ts
interface Named {
  name: string;
}
interface User extends Named {
  id: string;
}
type Result = User | { error: string };
```

## Extension

An interface can extend compatible object types with statically known members. Inherited properties must remain compatible. An interface cannot directly extend a union because a union does not supply a single fixed set of members.

```ts
interface Named {
  name: string;
}
// @ts-expect-error: the inherited property cannot change to number
interface Invalid extends Named {
  name: number;
}
```

An alias can express an intersection, but an intersection's property conflicts are handled differently. See [intersections](/typescript/types/intersections).

## Reopening declarations

Interface declarations with the same name in the same scope can merge. Compatible members accumulate. A type alias cannot be reopened this way.

```ts
interface Settings {
  timeout: number;
}
interface Settings {
  retries: number;
}
const settings: Settings = { timeout: 1_000, retries: 3 };
```

Merging is useful for extensible declaration surfaces, but unintended global interfaces can also merge. Make files modules when their declarations should be local.

## Names and identity

A named interface or type alias generally does not make a structurally compatible object nominal. Two object types can be assignable even when they have different names. Use a discriminant, a private member, or an explicit branded convention when a domain needs additional distinctions.

A branded type is still a checking convention and can be bypassed with an assertion. It does not validate runtime input.

See [interfaces and aliases](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#differences-between-type-aliases-and-interfaces) and [declaration merging](/typescript/declarations/merging).

## Declaration requirements

An interface names an object type containing properties, methods, call signatures, construct signatures, accessors, and index signatures. Its body does not contain implementations or initializers. It can be generic and can extend permitted object types or intersections whose members are statically known.

An interface cannot directly extend a primitive, union, or an unresolved generic operation without the required known object members. Inherited declarations must be mutually compatible; incompatible property types are diagnosed at the extending interface.

```ts
interface Base {
  value: string;
}
interface Derived extends Base {
  extra: number;
}
// @ts-expect-error: the inherited property cannot be replaced with an incompatible type
interface Broken extends Base {
  value: number;
}
type Choice = { left: string } | { right: number };
// @ts-expect-error: union members are not statically known interface heritage
interface Either extends Choice {}
```

## Structural meaning

An interface describes the required members; it does not produce a constructor or enforce exact runtime keys. Extra properties in an existing structurally compatible value can remain. A fresh object literal receives the additional excess-property checks defined in [object types](/typescript/types/objects).

An interface extending a class can inherit private and protected member origins. That interface can then restrict implementation to compatible descendants, despite ordinarily structural public members. The declaration origin, not the interface's name alone, provides the restriction.

## Generic interfaces

Parameters have constraints and optional defaults. Type arguments instantiate members and signatures. Parameters can carry permitted `in`/`out` variance annotations; their claimed relationship is validated, and their effect is limited to the comparison contexts described in [variance](/typescript/type-system/variance).

```ts
interface Container<T = unknown> {
  value: T;
}
const number: Container<number> = { value: 1 };
const unspecified: Container = { value: 'text' };
```

Defaults select omitted arguments; they do not make member values optional or introduce a runtime default.

## Open declarations and merging

Compatible declarations with the same interface name can merge. Nonmethod members must have the required consistent type and optionality. Generic parameter lists must be compatible. Method declarations contribute overloads whose order follows merging rules, including priority for supported specialized signatures.

This open behavior distinguishes interfaces from type aliases. An interface cannot be treated as an exact closed record solely because one source file lists a finite set of properties. In some index-signature comparisons, an alias to an object literal can receive implicit index compatibility that an augmentable interface does not.

## `implements` and output

A class `implements` clause checks its instance members against the interface. It does not generate missing members, validate runtime objects, or contextually annotate every method parameter. Interface declarations disappear from JavaScript output, while their exported form can remain in `.d.ts` files.
