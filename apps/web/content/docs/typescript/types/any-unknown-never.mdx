---
title: any, unknown, and never
description: Unchecked values, unknown values, and types with no possible values.
---

`any`, `unknown`, and `never` have different roles in checking. They are not interchangeable ways to avoid choosing a type.

| Type      | Assigning values to it | Using a value of it                                     |
| --------- | ---------------------- | ------------------------------------------------------- |
| `any`     | Accepts other types.   | Most operations bypass checking.                        |
| `unknown` | Accepts other types.   | Requires narrowing or an assertion for most operations. |
| `never`   | Accepts only `never`.  | Represents a value that cannot occur.                   |

## `unknown`

Use `unknown` when the shape of a value has not been established. A guard can make operations available:

```ts
function read(value: unknown): string {
  if (typeof value === 'string') return value.toUpperCase();
  return '(not a string)';
}
```

## `any`

`any` allows unchecked property accesses and calls, and is assignable to most target types. It is not assignable to `never`. An `any` value can propagate into the types of subsequent expressions.

An explicit `any` is permitted under `noImplicitAny`; that option rejects certain implicitly inferred `any` types. It does not eliminate all `any` from a program.

## `never`

A function annotated `never` must not complete normally. A narrowed variable can become `never` when no union member remains.

```ts
function unreachable(value: never): never {
  throw new Error(`Unexpected value: ${value}`);
}

function format(value: string | number) {
  if (typeof value === 'string') return value;
  if (typeof value === 'number') return String(value);
  return unreachable(value);
}
```

`never` disappears from ordinary unions: `string | never` is `string`. An intersection can become `never` when its requirements cannot both hold. See [intersections](/typescript/types/intersections).
