A class declaration creates a runtime constructor value and an instance type. `typeof ClassName` describes the constructor and static members; `ClassName` in a type position describes instances.

```ts
class Counter {
  value = 0;
  increment() {
    this.value += 1;
  }
}
const counter: Counter = new Counter();
const Constructor: typeof Counter = Counter;
```

## Members and initialization

Fields can infer their types from initializers. `strictPropertyInitialization` checks that relevant instance fields are initialized by a field initializer or in the constructor. A definite assignment assertion (`field!: T`) suppresses that check; it does not perform an assignment.

A constructor parameter with an accessibility modifier or `readonly` can declare a parameter property. It creates an instance property initialized from the argument.

## Visibility

`public` is the default. `protected` permits access within the class and derived classes under TypeScript's protected-access rules. TypeScript `private` restricts checking but does not create JavaScript private storage. A `#field` uses JavaScript's private-field semantics.

```ts
class Account {
  #balance = 0;
  deposit(amount: number) {
    this.#balance += amount;
  }
  get balance() {
    return this.#balance;
  }
}
```

## Compatibility

Public instance members participate in structural compatibility. Private and protected members add declaration-origin requirements: independently declared private members with the same spelling do not make two classes compatible.

## Inheritance

`extends` establishes runtime inheritance. `implements` checks the instance against an interface but does not alter method inference or generate an implementation. Abstract classes can supply implementation while preventing direct construction. Static members belong to the constructor, not the instance.

Field runtime semantics depend on `target` and `useDefineForClassFields`. See [classes](https://www.typescriptlang.org/docs/handbook/2/classes.html) and [emit](/typescript/projects/emit).

## Class declaration meanings

A class introduces an instance type and a constructor value. The instance type contains instance members and origin information for private/protected members. The constructor value contains construct signatures and static members. Generic parameters parameterize the instance side; a static member cannot refer to an instance type parameter as though each constructor object had a distinct instantiation.

```ts
class Box<T> {
  constructor(public value: T) {}
  // @ts-expect-error: static members cannot use the instance type parameter
  static defaultValue: T;
}
const box: Box<number> = new Box(1);
const constructor: typeof Box = Box;
```

## Member checking

A member may be a field, method, getter, setter, auto-accessor, or ECMAScript static block. Accessibility modifiers, `readonly`, `abstract`, `override`, `static`, optionality, and definite-assignment assertions apply only in their permitted combinations. A constructor parameter with accessibility or readonly modifiers declares and initializes a parameter property.

`public` is the default accessibility. TypeScript `private` restricts checked access but ordinarily emits an ordinary property; ECMAScript `#private` has runtime private-name semantics. `protected` permits access through the declaring class and derived-class rules, including restrictions on the receiver type used inside a subclass.

## Class compatibility

Public members are compared structurally. When a target requires a private or protected member, a structurally matching name alone is insufficient: its origin must be compatible with the target's declaration. Private identifiers likewise preserve declaration-specific identity in structural comparisons.

```ts
class Left {
  private brand = 0;
  value = 1;
}
class Right {
  private brand = 0;
  value = 1;
}
// @ts-expect-error: private members originate in different declarations
const left: Left = new Right();
```

Two classes without origin-restricted members can be mutually assignable despite different constructor names. A class does not acquire a universal nominal identity merely by using class syntax.

## Heritage and implementation

`extends` supplies a runtime base constructor and checks inherited members for compatibility. Instance overrides must satisfy the inherited contract. `implements` checks a class's instance type against the declared interface or object requirements; it neither copies members nor supplies contextual parameter annotations to method bodies.

```ts
interface Named {
  name: string;
}
class Item implements Named {
  constructor(public name: string) {}
}
interface Runner {
  run(value: string): void;
}
class Task implements Runner {
  // @ts-expect-error: implements does not contextually type this parameter
  run(value) {}
}
```

`noImplicitOverride` requires appropriate overriding declarations to say `override`; `override` itself requires a corresponding inherited member. Abstract members must be implemented by nonabstract derived classes. Abstract classes cannot be directly constructed through an abstract constructor value.

## Initialization and definite assignment

Under `strictPropertyInitialization` and strict null checking, an instance property whose type excludes undefined must be initialized in its declaration or definitely assigned through the constructor's recognized paths. Assignments hidden in another method do not generally establish constructor initialization. A `!` declaration assertion disables that proof obligation without inserting an initializer.

```ts
class Ready {
  value: string;
  constructor(value: string) {
    this.value = value;
  }
}
class External {
  value!: string;
}
```

ECMAScript determines base/derived field evaluation order and the availability of `this` around `super()`. `useDefineForClassFields` affects emitted field semantics, including inherited setters. `declare` fields describe types without producing field initialization. Static blocks and computed property names are runtime code, not erased type declarations.

## Accessors and `this`

Getter and setter read/write types can differ when explicitly declared under the edition's rules. A readonly field restricts checked writes, except permitted initialization in its declaring constructor. Polymorphic `this` represents the current subtype in instance positions; static and explicit `this` contexts follow separate rules in [this types](/typescript/type-system/this-types).
