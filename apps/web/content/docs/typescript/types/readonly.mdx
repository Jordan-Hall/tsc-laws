---
title: Readonly types
description: Write restrictions through a type, their shallow scope, and mutable aliases.
---

`readonly` prevents certain writes through the annotated type. It is a checking restriction, not runtime freezing.

```ts
type User = { readonly id: string; profile: { name: string } };
const user: User = { id: '1', profile: { name: 'Ada' } };
// @ts-expect-error: id is readonly through User
user.id = '2';
user.profile.name = 'Grace'; // nested object is still mutable
```

## Shallow behavior

`Readonly<T>` makes the properties of `T` readonly; it does not recursively transform every referenced value. Similarly, a readonly array restricts array writes while its element objects may remain mutable.

```ts
const users: readonly { name: string }[] = [{ name: 'Ada' }];
// @ts-expect-error: push is not available on the readonly view
users.push({ name: 'Lin' });
for (const user of users) user.name = 'Grace';
```

## Aliasing

Another reference can observe and mutate the same object. TypeScript does not generally use readonly object properties as a nominal compatibility boundary.

```ts
const mutable = { count: 0 };
const view: Readonly<typeof mutable> = mutable;
mutable.count = 1;
const observed = view.count; // observes the same object's property
```

Readonly array compatibility is stricter: a readonly array cannot ordinarily be assigned to a mutable array type because it lacks the mutation surface.

## Const assertions

`as const` preserves literal types and produces readonly properties or readonly tuple positions for the literal structure. A referenced mutable object remains mutable; a const assertion does not recursively freeze external references.

Use `Object.freeze` when runtime freezing is needed, remembering that its ordinary behavior is also shallow.

See [readonly properties](https://www.typescriptlang.org/docs/handbook/2/objects.html#readonly-properties), [mapped modifiers](/typescript/type-operators/mapped-types), and [assertions](/typescript/type-system/assertions).

## Readonly member rules

A readonly property can be read but cannot be assigned through a checked receiver exposing that declaration, except permitted initialization in its declaring class. Readonly is not a runtime descriptor, an object freeze, or a recursive immutability guarantee.

Ordinary structural object assignment often does not use readonly property modifiers to prohibit assigning a readonly object view to a mutable property shape. This differs from readonly arrays and tuples, whose omitted mutation capabilities prevent assignment to mutable array/tuple targets.

```ts
const readonlyObject: { readonly count: number } = { count: 0 };
const mutableAlias: { count: number } = readonlyObject;
mutableAlias.count = 1;
// @ts-expect-error: a write through this readonly view is prohibited
readonlyObject.count = 2;
```

The rule must not be summarized as universal covariance from mutable objects to readonly objects with a forbidden reverse direction. Arrays, tuples, and ordinary properties have different compatibility mechanisms.

## Nested member mutability

A readonly property containing a mutable object restricts replacing that property, not writing through the nested object's own mutable members. A readonly array restricts its element slots and mutation methods, not every property of each element.

```ts
const view: Readonly<{ nested: { count: number } }> = { nested: { count: 0 } };
view.nested.count += 1;
// @ts-expect-error: the outer property cannot be replaced
view.nested = { count: 2 };
```

`const` restricts rebinding a variable; readonly restricts a member or array interface. A const assertion recursively processes contained literal syntax but leaves referenced mutable entities mutable.

## Mapped modifiers

Mapped types can add or remove readonly with `readonly`, `+readonly`, and `-readonly`. A homomorphic mapping preserves member relationships and can convert arrays or tuples to readonly or mutable counterparts. Applying readonly to arbitrary non-array type syntax with the type operator is rejected; `readonly` is not a general prefix for every type.

```ts
type Mutable<T> = { -readonly [K in keyof T]: T[K] };
type Frozen = readonly [string, number];
const mutable: Mutable<Frozen> = ['a', 1];
mutable[0] = 'b';
```

## Accessors and assignment targets

A getter-only property is read-only through its exposed accessor contract. Getter and setter types can separately describe accepted writes and returned reads. Destructuring reads values; it does not transfer a readonly modifier to the new local binding. A readonly view can therefore be read into an ordinary mutable local variable of the property's value type.
