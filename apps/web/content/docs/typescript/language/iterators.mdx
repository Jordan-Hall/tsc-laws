An iterable supplies a method at `Symbol.iterator`. Calling that method returns an iterator, whose `next` method produces iterator results. `for...of` uses this protocol to read values.

```ts
function* numbers(): Generator<number, void, unknown> {
  yield 1;
  yield 2;
}

for (const number of numbers()) {
  number.toFixed();
}
```

## Generator types

`Generator<TYield, TReturn, TNext>` distinguishes values yielded to the consumer, the final return value, and values accepted by `next`. A `yield` expression inside the generator receives a value passed by the consumer.

```ts
function* ask(): Generator<string, number, boolean> {
  const accepted = yield 'Continue?';
  return accepted ? 1 : 0;
}

const iterator = ask();
iterator.next();
const result = iterator.next(true);
if (result.done) result.value.toFixed(); // final number
```

The `done` property distinguishes a yield result from a return result. The iterator's return type can differ from its yielded element type.

## Async iteration

An async iterable provides `Symbol.asyncIterator`. `for await...of` awaits iteration results and can also consume synchronous iterables. Async generators expose the async iterator protocol.

```ts
async function* values(): AsyncGenerator<string, void, unknown> {
  yield 'first';
}

async function consume() {
  for await (const value of values()) console.log(value);
}
```

## Targets and libraries

Library declarations describe available iterator and generator APIs. When targeting older JavaScript, `downlevelIteration` affects certain emitted iteration operations. A compiler helper cannot supply every missing platform API; the runtime may still need `Symbol` or other support.

See [iterators and generators](https://www.typescriptlang.org/docs/handbook/iterators-and-generators.html) and [emit](/typescript/projects/emit).
