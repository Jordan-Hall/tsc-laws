title: Iterators and generators
description: Iterable values, iterator results, generators, and async iteration.

An iterable supplies a method at `Symbol.iterator`. Calling that method returns an iterator, whose `next` method produces iterator results. `for...of` uses this protocol to read values.

```ts
function* numbers(): Generator<number, void, unknown> {
  yield 1;
  yield 2;
}

for (const number of numbers()) {
  number.toFixed();
}
```

## Generator types

`Generator<TYield, TReturn, TNext>` distinguishes values yielded to the consumer, the final return value, and values accepted by `next`. A `yield` expression inside the generator receives a value passed by the consumer.

```ts
function* ask(): Generator<string, number, boolean> {
  const accepted = yield 'Continue?';
  return accepted ? 1 : 0;
}

const iterator = ask();
iterator.next();
const result = iterator.next(true);
if (result.done) result.value.toFixed(); // final number
```

The `done` property distinguishes a yield result from a return result. The iterator's return type can differ from its yielded element type.

## Async iteration

An async iterable provides `Symbol.asyncIterator`. `for await...of` awaits iteration results and can also consume synchronous iterables. Async generators expose the async iterator protocol.

```ts
async function* values(): AsyncGenerator<string, void, unknown> {
  yield 'first';
}

async function consume() {
  for await (const value of values()) console.log(value);
}
```

## Targets and libraries

Library declarations describe available iterator and generator APIs. When targeting older JavaScript, `downlevelIteration` affects certain emitted iteration operations. A compiler helper cannot supply every missing platform API; the runtime may still need `Symbol` or other support.

See [iterators and generators](https://www.typescriptlang.org/docs/handbook/iterators-and-generators.html) and [emit](/typescript/projects/emit).

## Protocol records

An iterable supplies a method at `Symbol.iterator`; an iterator supplies `next` and optionally `return`/`throw`. A returned iterator result distinguishes a yielded `value` from a completed result using `done`. The library models yield, return, and next-input types independently.

```ts
function* sequence(): Generator<string, number, boolean> {
  const input: boolean = yield 'ready';
  return input ? 1 : 0;
}
const iterator = sequence();
const initial = iterator.next();
const following = iterator.next(true);
```

The first resume does not pass a meaningful value into an already-suspended yield. An annotation does not cause JavaScript to validate later next-input values.

## CheckIteration

For an iterable operation:

1. Obtain the applicable synchronous or asynchronous iterator contract from the operand type.
2. Determine the produced element type through its iterator result relationship.
3. Check the loop binding, spread, destructuring, or delegating yield target against the produced values.
4. Apply target and downlevel transform requirements.

At an older target, `downlevelIteration` affects protocol-aware emit. Without it, some operations are restricted to array-like behavior. Library selection and runtime implementation remain separate requirements.

## Iterator result narrowing

Testing `done` can distinguish the yield type from the completion return type. Directly reading `value` without checking completion can therefore include both. Under strict builtin-iterator-return behavior in this edition, built-in iterators no longer universally expose an any completion value.

```ts
const iterator = new Set(['a']).values();
const result = iterator.next();
const possible: string | undefined = result.value;
if (!result.done) {
  const yielded: string = result.value;
}
```

`strictBuiltinIteratorReturn` affects the built-in declarations' intrinsic return relationship and is included in strict checking. A custom generator can declare its own distinct return type.

## Delegation and asynchronous forms

`yield*` delegates to another iterable and checks its yielded, returned, and next-input relationships. The delegate's return contributes the yield-star expression result rather than becoming another ordinary yielded element. Async delegation and `for await...of` use their async protocol rules and supported synchronous fallback.

TypeScript 5.6 introduced iterator helper declarations and the `IteratorObject` family. Their presence depends on the selected library. Typing a helper such as mapping an iterator does not polyfill that method on an older runtime.

## Cleanup and abrupt exits

Iterator closing on abrupt completion follows ECMAScript. A loop's accepted element type does not prove its iterator has no side effects, never throws, or closes without failure. Resource-management bindings inside loops have additional disposal behavior described separately.
