title: Expressions
description: Operators, property access, calls, and optional access in checked JavaScript.

An expression produces a value or performs an operation on values. TypeScript checks its operands and assigns the expression a type. JavaScript determines how the expression evaluates.

## Operators

Arithmetic operators generally require numeric operands. `+` also supports string concatenation. Number and bigint arithmetic cannot mix operands without an explicit conversion.

```ts
const total = 1 + 2;
const text = 'count: ' + total;
const big = 1n + 2n;

// @ts-expect-error: number and bigint cannot be mixed
const mixed = 1n + 2;
```

The type checker does not generally compute the exact literal result of arithmetic. The type of `1 + 2` is `number`, not `3`.

## Property access and calls

Property access requires a property available on the receiver type. A call requires a compatible call signature and arguments. For a union, an operation must be valid for the possible members that remain after narrowing.

```ts
function length(value: string | string[]) {
  return value.length; // shared property, number
}
```

## Optional chaining and nullish coalescing

Optional chaining stops an access or call when its receiver is `null` or `undefined`. It does not stop for `0`, `false`, or an empty string. `??` selects its right operand only when the left is nullish.

```ts
declare const settings: { retries?: number } | undefined;
const retries = settings?.retries ?? 3; // number
```

An optional chain protects the portion of access that belongs to the chain. It does not prove that every nested property is present. Use additional optional access when an intermediate property is also optional.

## Assignment expressions

An assignment is checked against the target's declared type. Its use can also change the flow type of a variable. Type assertions affect checking but do not convert the assigned value.

See [everyday types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html), [narrowing](/typescript/type-system/narrowing), and the [ECMAScript expressions grammar](https://tc39.es/ecma262/#sec-ecmascript-language-expressions).

## Operator checking

Expression evaluation and coercion follow ECMAScript; TypeScript additionally checks operand types and computes a static result. An operation's runtime permissiveness does not imply that every coercible operand is accepted by the checker.

| Operation                 | Static requirements or result                                                                             |
| ------------------------- | --------------------------------------------------------------------------------------------------------- |
| Arithmetic other than `+` | Numeric/enum/bigint or dynamic operands as permitted; number and bigint cannot be mixed indiscriminately. |
| `+`                       | Apply the edition's string/numeric operand rules; result can be string or numeric according to operands.  |
| Unary `+`                 | Numeric coercion rules do not make bigint a permitted operand.                                            |
| Equality                  | Check comparable operand types and establish supported branch facts.                                      |
| Relational operators      | Require an applicable operand relationship; comparisons are not assertions.                               |
| `&&`, `\|\|`, `??`        | Compute result possibilities from truthiness or nullishness, not always boolean.                          |
| `!`                       | Boolean result and recognized inverse truthiness facts.                                                   |
| `typeof`                  | Runtime string result with narrowing in supported comparisons.                                            |
| `in`, `instanceof`        | Operand restrictions plus recognized presence/instance facts.                                             |
| Comma                     | Evaluate operands and use the final expression's result type.                                             |

```ts
declare const optional: string | undefined;
const fallback: string = optional ?? 'default';
declare const flag: boolean;
const selected: string | false = flag && 'text';
```

## Property and element access

Resolve named members or index signatures from the receiver's apparent type. A nullable receiver needs narrowing, optional chaining, or an assertion under strict null checking. An unknown receiver cannot be arbitrarily indexed. Private identifiers and TypeScript accessibility introduce additional restrictions.

Optional chaining short-circuits the chain at a nullish receiver. It does not make every later independent operation safe. The static result includes undefined when a chain can short-circuit. An optional call is not a construct expression and cannot be used as an arbitrary assignment target.

## Assignments and compound updates

An assignment requires a writable target and a value satisfying its target type. Compound arithmetic and logical assignments also check the operation's result. Assigning through an uncertain union key can require an intersection of member write types. Destructuring assignments use runtime patterns while checking selected target locations.

With strict null checking, deleting a required property can be rejected; an optional property is a valid candidate according to the applicable rules. Readonly status, accessors, and origin restrictions apply independently of runtime configurability.

```ts
const record: { required: string; optional?: string } = { required: 'a' };
delete record.optional;
// @ts-expect-error: a required member cannot be deleted in this strict context
delete record.required;
```

## Calls, constructs, and literals

Calls and `new` use their signatures, arity, inference, and overload rules. Tagged templates are calls with the template strings object and substitution arguments. Array and object literals use contextual typing, spreading, freshness, and widening. Function expressions and arrows introduce checking contexts for parameters, returns, generics, and receivers.

## Erased expression forms

Type assertions, const assertions, `satisfies`, non-null assertions, and type arguments are erased after checking. Instantiation expressions preserve the underlying value. None changes JavaScript coercion, provides a runtime guard, or wraps the expression in a validator.
