---
title: Variables and bindings
description: Declare values with const, let, and var, including destructuring bindings.
---

`const` and `let` declare block-scoped bindings. `const` requires an initializer and prevents assigning another value to the binding. It does not freeze the value.

```ts
const user = { name: 'Ada' };
user.name = 'Grace'; // the object's property is mutable

// @ts-expect-error: a const binding cannot be reassigned
user = { name: 'Lin' };

let attempts = 0;
attempts += 1;
```

## Annotations and inference

An annotation sets the binding's declared type. Without one, the initializer and context supply a type.

```ts
let mode = 'read'; // string
const fixed = 'read'; // "read"
let selected: 'read' | 'write' = fixed;
selected = 'write';

// @ts-expect-error: "delete" is outside the declared union
selected = 'delete';
```

`let` usually widens primitive literal initializers because later assignments are allowed. Object properties can widen even when the binding uses `const`. Use [const assertions](/typescript/type-system/assertions) when a literal expression should retain its literal structure.

## Destructuring

Destructuring introduces bindings from object properties or iterable elements. Defaults apply when the extracted value is `undefined`, not when it is `null`.

```ts
const options: { timeout?: number } = {};
const { timeout = 1_000 } = options;
const [first, second] = ['a', 'b'] as const;
```

A destructuring annotation describes the source value's shape. In `{ name: label }`, `label` is the new variable name; `name` is not a type annotation.

## `var`

`var` is scoped to a function or script rather than the nearest block. Its declaration is hoisted and its runtime value starts as `undefined` before the initializer executes. `let` and `const` have a temporal dead zone before initialization.

See [variable declarations](https://www.typescriptlang.org/docs/handbook/variable-declarations.html) and [scope](/typescript/language/scopes).
