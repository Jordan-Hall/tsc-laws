---
title: Explicit resource management
description: Using and await using declarations, disposal contracts, lexical lifetimes, loop resources, and abrupt completion.
---

`using` and `await using` declare resources with cleanup at the end of their scope. Their types establish a disposal contract; their runtime behavior includes disposal and error handling rather than simple type erasure.

## Declaration grammar

```text
ResourceDeclaration = [ 'await' ] 'using' ResourceBinding
                      { ',' ResourceBinding } [ ';' ] ;
ResourceBinding = Identifier [ ':' Type ] '=' AssignmentExpression ;
ResourceForBinding = [ 'await' ] 'using' Identifier ;
```

An ordinary resource binding requires an initializer and can have an annotation. A `for...of` resource binding receives its initializer from iteration and cannot include an annotation or explicit initializer. Bindings are single identifiers rather than object/array binding patterns. `await using` requires an allowed asynchronous context. A line break cannot separate `await` from `using` or `using` from its binding. Resource declarations cannot be ambient or exported. A resource cannot be reassigned like an ordinary `let` binding.

## Resource type checking

A synchronous resource must satisfy the supported `Symbol.dispose` callable contract, or be an admitted nullish value. An asynchronous resource uses `Symbol.asyncDispose` or the supported synchronous fallback. Library declarations for these symbols and interfaces must be available; they do not install runtime implementations.

```ts
// @option: lib=["ES2022","DOM","DOM.Iterable","ESNext.Disposable"]
class Resource implements Disposable {
  [Symbol.dispose](): void {}
}
function use() {
  using resource: Disposable = new Resource();
  return 'complete';
}
```

The example checks the declaration contract, not execution of disposal. A getter or disposer can throw at runtime despite its callable type.

## Scope exit

Resources acquired in a scope are disposed in reverse acquisition order when that scope completes. Completion includes normal fallthrough, return, throw, and applicable loop exits. A disposer is captured according to the resource operation's rules; later arbitrary property mutation is not a substitute for the captured contract.

If both the body and cleanup fail, the runtime protocol preserves the relevant error relationship through suppressed-error handling. TypeScript's helper-based emit models the required cleanup behavior for targets that need it. An annotation alone does not create that behavior.

## Asynchronous disposal

`await using` waits for asynchronous cleanup on scope exit. This differs from ordinary `using` even if the resource also provides a synchronous disposal method. Cleanup timing and Promise assimilation follow the resource protocol. The enclosing async function's result remains a Promise of its normal result type; that type does not enumerate disposal failures.

```ts
// @option: lib=["ES2022","DOM","DOM.Iterable","ESNext.Disposable"]
async function work(resource: AsyncDisposable) {
  await using acquired = resource;
  return 1;
}
```

## Loops and nullish resources

Resource bindings in `for...of` acquire and dispose each iteration's resource at the appropriate iteration scope. `for await...of` and an async resource binding have independent effects: asynchronous iteration does not automatically select asynchronous disposal, nor vice versa.

An admitted null or undefined initializer adds no ordinary disposer call. The async protocol still has its prescribed completion timing. A resource binding in an unsupported loop form or declaration context is a diagnostic.

## Output and implementation boundaries

Resource declarations can require helpers and runtime symbols; selecting an old target does not provide all runtime facilities by itself. `erasableSyntaxOnly` and independent-transform options must be considered when the surrounding tool only strips types. Scope-based resource management does not prove that another alias cannot outlive the resource or use it after disposal; TypeScript does not supply a general linear ownership type system.
